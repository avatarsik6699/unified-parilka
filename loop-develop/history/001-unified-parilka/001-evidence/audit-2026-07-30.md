# Goal 001 evidence: аудит исходных репозиториев — 2026-07-30

## Scope

- Python bot: legacy checkout, HEAD `a53aa48`
- Telegram MCP: legacy checkout, исходный HEAD `459697b`
- Production: systemd user services на аудитируемом хосте

Секреты и содержимое credential files не читались. Live Telegram sends во время
аудита не выполнялись.

## Production baseline

- Python bot за 24 часа: 136 starts, 131 sent, 3 failed; p50 14.3 s, p90
  45.1 s, max 147 s.
- Наблюдались 20 overlap-пар при разрешённой concurrency 3.
- Было 45–46 quote guard warnings, 29 stranded folds и пять watchdog restarts.
- MTProto sync не имел успеха с 2026-07-25, накопил 1769 consecutive failures
  и тысячи raw GramJS TIMEOUT строк.
- Live corpus SQLite: `quick_check=ok`, schema v10, примерно 224k сообщений.
- `history_jobs`: около 76k строк и 11.3 MiB; девять jobs навсегда остались
  `running`.

## Критические дефекты Python bot

1. Один общий pending/running state обслуживал до трёх turn и маршрутизировал
   follow-up случайному ходу.
2. Bot API offset сохранялся после spawn thread, но до durable outbox
   reservation; crash терял trigger навсегда.
3. Raw model stream публиковался до quote/think/mention guards.
4. JSONL + SQLite + NPY embedding generation не была crash-consistent.
5. Declared turn deadline не применялся.
6. Tail-only indexing игнорировал edits/deletes и ежедневно отставал.
7. Chunker нарушал hard character limit на длинном URL/token.
8. Maintenance мог закончиться exit 0 после фактической ошибки.
9. Prompt разрешал person lookup, а tool всё ещё запрещал.
10. Quote guard проверял текст, но не автора.
11. UTC digest windows расходились с Moscow-facing contract.
12. Не было graceful drain.
13. Structured events не везде имели `turn_id` и provider spans.
14. systemd append-логи не ротировались.
15. Provider/model/endpoints были размазаны по модулям без fallback.

## Критические и высокие дефекты MCP

В ходе аудита уже исправлены в production:

- multi-tick catch-up livelock;
- GramJS client loop leak;
- raw GramJS log storm;
- устаревший MCP SDK dependency chain;
- retry одного `sending` outbox row после TTL;
- переписывание живого `sending` вторым MCP process;
- blind retry после неоднозначного Telegram dispatch.

Оставшиеся migration items:

- заменить архивированный GramJS на mtcute;
- сделать одного владельца MTProto client/scheduler;
- отделить human confirmation от self-issued payload capability;
- редактировать credentials в embedding estimate/namespace;
- manual backfill не должен менять daemon exhausted state;
- failed recent sync не должен обновлять success timestamp;
- timeout должен отменять underlying iterator;
- удалить бесконечную exhausted-backfill job telemetry и добавить retention;
- сделать embedding build staging/atomic;
- добавить graceful shutdown и connection singleton;
- заменить root-specific runbook/user units.

## Сохранить при переносе

- Явное упоминание bot username/text_mention — единственный trigger.
- Reply на bot message без mention не триггерит.
- Edits ingestятся, но не создают turn.
- UTF-16 entity offsets, captions, sender_chat и media placeholders.
- L0 recent window, L1 day digests, L2 weekly rollups.
- Hybrid BM25 + dense RRF и asymmetric embedding task type.
- `search_chat`, `thread_context`, `day_digest`, `web_search`.
- Owner follow-up отдельно от ambient chatter.
- Fold только на tool/model boundary.
- Exact `SKIP` как no-send.
- Forced final response после bounded tool loop.
- Tool errors возвращаются модели как typed data.
- Reply к конкретному trigger.
- Read-only model tool registry.
- Allowlist, hard dry-run, durable outbox, tombstones, cache completeness и
  contiguous sync cursor.

## Не переносить

- Python thread model и общий pending state;
- raw public streaming;
- JSONL/NPY как transactional index;
- 2400-строчный store и 1200-строчный tool router без разбиения;
- GramJS client в каждом stdio process;
- in-memory cross-process send scheduler;
- self-issued `approval_id` как «human approval»;
- бесконечный job audit;
- append-only process logs;
- historical TODO-файлы как runbook.

## Обязательный cutover gate

До переключения production новая версия должна пройти:

1. Telegram characterization fixtures.
2. Три перекрывающихся turn и два turn одного sender.
3. Crash matrix для ingest/reserve/model/draft/ACK/status.
4. Provider timeout/429/5xx/auth/filter/malformed tool/empty output.
5. Prompt injection и wrong-speaker quote tests.
6. RAG regression, fresh delta, edit/delete, long URL и timezone ranges.
7. Import/restore обоих SQLite и rollback rehearsal.
8. Shadow run с cursor/count/hash comparison.
9. Финальный delta после остановки старого writer.
10. Только после smoke — включение live writes.
